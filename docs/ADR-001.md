# ADR-001: Technology Stack for FitFlow Redesign

**Status:** Accepted for the redesign prototype / first production version

## Context
FitFlow needs iOS, Android and web support, AI personalisation, camera nutrition logging, real-time social features, strong privacy and fast delivery by a mid-sized team.

## Decision
Use React Native for mobile, React for web, NestJS for the main backend, FastAPI for AI, PostgreSQL for core data, Redis/WebSockets for real-time features, Auth0 for identity, and TensorFlow Lite / ML Kit where practical.

## Main Reasons
Good code reuse, strong ecosystem, easier maintenance, separate AI scaling, reliable relational data and managed authentication.

## Trade-offs
- More than one backend technology is used.
- Auth0 can become expensive.
- Some native code may still be required for camera, health or AI features.

## Alternatives Considered
Flutter, Firebase-first backend, Kotlin Multiplatform and Go.

## Review Point
Review cost, performance and user growth after the first production release.
